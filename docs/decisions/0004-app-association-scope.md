# 0004 「常にこのアプリで開く」は、アプリ内だけの関連付けにする

日付: 2026-10-01 / 対象: 仕様書34章「アプリで開く」/ Issue #24

## 背景

仕様書34章に「常にこのアプリ」「拡張子関連付け管理」とある。素直に読むと、Windowsのファイル関連付け（既定のアプリ）を変更する機能になる。

## 決定

**このアプリの中だけで有効な関連付けとして実装し、Windowsのファイル関連付け（システム設定）は変更しない。**

- 関連付けは、設定（`settings.json`）に、拡張子ごとの「開くアプリ」として保存する。
- このアプリでファイルを開くとき（Enter・ダブルクリック）に、関連付けがあれば、そのアプリで開く。
- Windowsの「既定のアプリ」を変更したい場合は、Windowsの設定画面（設定 → アプリ → 既定のアプリ）で行う。

## 理由

1. **Windows 10/11では、レジストリの直接の書き換えができない。** ユーザーが選んだ既定のアプリ（`UserChoice`）は、ハッシュで保護されていて、ハッシュを偽造して書き込む方法は、Windowsが意図して禁止している仕組みを回避することになる（また、Windowsの更新で壊れ、設定が無効化・リセットされる）。
2. **影響範囲が大きい。** システムの関連付けを誤って書き換えると、このアプリ以外（ExplorerやOfficeなど）でのファイルの開き方まで変わってしまい、利用者が元に戻しにくい。
3. **このアプリの目的に十分。** 利用者が困るのは「このアプリで、この種類のファイルを、いつものエディターで開きたい」場面で、システム全体の設定を変える必要はない。
4. **安全。** 関連付けを解除・変更するのも、設定画面で完結する。システムには何も残らない。

## 補足

- 関連付けたアプリが見つからないときは、既定のアプリで開く（開けないままにしない）。
- 「インストール済みアプリ候補」の一覧は、今回は作らない（任意のEXEを選ぶ方式）。必要になったら、別のIssueで扱う。
