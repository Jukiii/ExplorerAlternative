# 0003 「TerminalからExplorerへのドラッグ」の意味

日付: 2026-10-01 / 対象: 仕様書19章「ターミナル連携」/ Issue #27

## 背景

仕様書19章に「TerminalからExplorerへのドラッグ」とあるが、何をドラッグして、ドロップしたら何が起きるかは、書かれていない。

## 決定

**ターミナル上で選んだ文字列（パス）を、Explorerのペインへドラッグ&ドロップすると、そのフォルダ（ファイルなら、その場所）へ移動する。**

| ドロップした文字列 | 動作 |
| ------------------ | ---- |
| 存在するフォルダのパス | そのペインが、そのフォルダへ移動する（戻る操作で元に戻れる） |
| 存在するファイルのパス | そのファイルのあるフォルダへ移動し、ファイルを選択状態にする（すでにそのフォルダなら、選択だけ） |
| 相対パス | そのペインの現在のフォルダからのパスとして解釈する |
| パスではない文字列 | 何も移動せず、「存在するファイル・フォルダのパスではありません」と伝える |

## 理由

- 反対方向（Explorer → ターミナル：ファイル・フォルダをドラッグするとパスが入力される）と対になる、自然な操作。
- ターミナルの出力（`ls` の結果、`pwd`、エラーメッセージ中のパスなど）から、そのまま目的の場所へ移動できる。
- ファイルそのものの移動・コピーではなく「場所を開く」にしたのは、ターミナルの文字列は、ファイルの実体ではなく、パスの文字列にすぎないため。誤ってファイルを動かす危険がない。

## 文字列の解釈

ターミナルの出力から選んだ文字列には、余計なものが付くことがあるため、次の順で解釈する（`DroppedPathResolver`）。

1. 最初の空でない行だけを使い、前後の空白を除く。
2. 行頭のPowerShellのプロンプト（`PS C:\foo> `）は除く。
3. 前後の引用符（`"` または `'`）は除く。
4. 環境変数（`%USERPROFILE%`）は展開する。
5. 実在するファイル・フォルダのときだけ、成功とする。
