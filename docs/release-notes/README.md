# リリースノート

`v<バージョン>.md`（例：`v1.3.3.md`）に、そのリリースのノートを書く。タグ（`v1.3.3`）をプッシュすると、
リリースのワークフロー（`.github/workflows/release.yml`）が、このファイルをGitHub Releaseの本文に使う。
ファイルが無い場合は、GitHubの自動生成のノート（前回のリリースからの変更）になる。

書き方は、過去のリリース（GitHub Releases）に合わせる：

- 冒頭に、このリリースの位置づけを1〜2行で書く。
- 「修正した不具合」「追加・改善」などの見出しで、利用者に見える変更を書く。
- 「ダウンロード」「既知の制限」を書く。

リリースの手順は、`README.md` の「リリース手順」を参照。
